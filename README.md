# PERL clinical intelligence workspace

A dependency-free deployment candidate for Focused Future’s clinician-facing e-QPASS summary, review, calibration, and practice-operations workflow. The clinician experience and persistent API use the same application path locally, in deployment review, and in the hardened container contract.

> **Deployment-review ready · evaluation records only.** The software candidate is runnable and verifiable. PHI, authoritative e-QPASS connectivity, clinical validation, clinical release, traffic activation, and patient use remain subject to named external approval.

## Open the deployment candidate

On macOS, double-click `Launch PERL.command`, or run:

```bash
npm run preview:deployment
```

Open [http://127.0.0.1:4173](http://127.0.0.1:4173). This is the persistent, server-backed product path. Opening `index.html` directly now shows a deliberate interlock because a source file cannot exercise the deployed API, safety, audit, and readiness behavior.

See [DEPLOYMENT_CANDIDATE.md](./docs/DEPLOYMENT_CANDIDATE.md) for GitHub, container, verification, and production-approval boundaries.

## Engineering mode

Node 18 or newer:

```bash
npm start
```

No dependency install step is required. Use the PERL server rather than a static file server so persistence, validation, audit history, safety mutations, and readiness all follow the deployment path.

When run through `npm start`, the interface connects to a loopback-only synthetic API and persists state in `data/sandbox-state.json`. Owner-only file permissions are applied. Opening `index.html` directly remains possible, but uses the visibly labeled in-memory fallback.

The default identity mode is a non-authenticated synthetic reviewer code. To exercise the fail-closed production identity seam, start with an owner-only `PERL_IDENTITY_ACCESS_POLICY_FILE`; protected API routes then require short-lived externally issued Ed25519 assertions and fixed RBAC. PERL never issues or stores the token. See [IDENTITY_ACCESS_PERIMETER.md](./docs/IDENTITY_ACCESS_PERIMETER.md).

## Product tour

- **Summary review:** inspect an evidence-linked draft, switch among clinician, care-coordination, payer, and minimum-necessary administrative formats, edit narrative or structured interpretation, review safety, approve, return feedback, and open the selected print/PDF presentation. A source-linked approval automatically prepares one idempotent synthetic handoff manifest; a failed preparation is visible and retryable. Once prepared, open the five-page Assembly Proof to inspect four source-owned placeholders followed by the exact approved synthetic PERL content and export its lineage manifest. Non-clinician previews cannot borrow or reopen clinician approval, and no PDF merge or e-QPASS attachment is claimed.
- **Review queue:** open three synthetic profiles with different score patterns and statuses.
- **Progress Review:** inspect a deliberately constructed two-point synthetic plate, compare exact raw movement and like-label subscales, read a deterministic affirming Conversation Brief, open its Letter-oriented rehearsal addendum, verify each point’s critical-screen route, and record only a structured next-question observation. The workflow never labels movement as improvement, issues a clinical recommendation, creates a progress note, or asserts a real-person longitudinal link.
- **Counselor Fieldwork:** enter a purpose-built provider-side briefing room, read the live synthetic denominator and safety state, walk the three-session runway, open the priority summary or blind comparison in one move, and carry a fixed decision into the structured Session Notebook. The room makes named-panel, source-sample, intended-use, language, provider-rehearsal, and independent-review readiness visible while keeping identity, attendance, narrative notes, training completion, clinical acceptance, and patient use outside the product.
- **Campus operations:** inspect a premium aggregate observatory for the North Central and Cooper source pathways; move among admission, quarter-one, midyear, and closeout questions; read six measures with visible denominators; inspect training readiness; and seal only an enum working position on page customization. The surface shows zero student records and cannot verify a site, quarter, completed review, pilot, outcome, or authorization.
- **Clinical Standard:** before inspecting outcomes, define seven preference, quality, correction, agreement, and workflow thresholds beside four fixed safety limits. Each save creates an immutable version, pins the evidence state at creation, and stays visibly unaccepted; a late draft can never masquerade as pre-results intent.
- **Independent Review:** inspect the six-domain third-party review question, four local evidence patterns, six outside decisions, eight controlled inputs, exact evidence counts, runtime provenance, and ledger heads. Export or seal the local dossier without naming an evaluator or creating an accuracy, reliability, validity, pilot, release, or patient-use decision.
- **Calibration:** begin with the aggregate-only Intake Studio, which keeps the proposal’s source-reported `~600` assessments separate from `0` received or inspected records and turns cohort readiness into five gates and nine required returns. Use the Model Trial Bench to preflight exactly three AI candidate descriptions against the same six-domain standard while keeping credentials, endpoints, source content, provider calls, verification, and selection outside the sandbox. Then inspect the fixed 9-run/12-blind Candidate Trial, manually receive bounded outputs, and—only after all six evidence gates close—review four anonymous A–D summaries against one scored source. Once all three cases have independent overlap, move into the Candidate Refinement & Retest Lab: recurring corrections may scope one declared change and three same-case envelopes, while unsafe lanes leave optimization for triage and no candidate becomes a winner. ## Deployment

For a private prototype review, run the loopback server or publish the static interface only inside an approved private review channel. Do not upload real respondent data.

Production deployment is a different system: it belongs inside the approved e-QPASS Azure environment with RBAC, encryption, audited data flow, approved model hosting, immutable review history, monitoring, backups, and completed clinical/legal/security validation. The [runtime envelope](./docs/PRODUCTION_RUNTIME_ENVELOPE.md) supplies a tested container contract, not evidence that this external deployment occurred. See [docs/PRODUCTION_ROADMAP.md](./docs/PRODUCTION_ROADMAP.md).
