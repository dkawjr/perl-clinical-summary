# PERL launch readiness plan

## Purpose

This is the working path from the current synthetic product slice to a limited provider pilot. It answers the timing, ownership, security, backup, and release questions in Dolores's correspondence without treating a vendor estimate as clinical proof.

The planning window is fourteen weeks after the named owners, approved data path, and counselor panel are available. The window is directional. A gate moves only when its evidence exists. Missing authorization, source mapping, legal language, clinical reviewers, or an independent evaluator stops the clock.

The Governance view now renders this plan through `perl-marketability-map/1.0`. Its four-phase executive runway is read-only and derives its counts from the live Permission Ledger; it cannot start the clock, assign authority, accept evidence, make a funding representation, or turn a working local rehearsal into market or pilot readiness. See [MARKETABILITY_MAP.md](./MARKETABILITY_MAP.md).

The companion `perl-executive-handoff/1.0` Decision Room converts the same plan into a controlled working-session packet for Dolores, Mike, the e-QPASS owner, clinical/legal/security/accessibility owners, counselors, and the independent evaluator. ## Critical path

1. Intended use must be fixed before legal language, model evaluation, and counselor rating criteria can be frozen.
2. The authoritative e-QPASS scored payload must be signed before clinical cases, integration, or report provenance can be trusted.
3. Development cases and counselor corrections must stabilize the candidate before the unseen holdout is opened.
4. Independent review and production-control evidence must both pass before pilot authorization.
5. The report service must attach PERL beside the unchanged Findings report and preserve both records.
6. Backup restoration and application rollback must be demonstrated before a pilot record can depend on the system.
